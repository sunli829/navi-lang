# 编译速度基准（计划第 6 节）

`tools/bench.sh <navic> [行数...]` 用 `bench/gen` 生成等价的 navi 和 Go 项目（每个单元一个结构体、一个枚举、几个用到循环/Vec/HashMap/match/闭包/格式化的函数），测：

- 冷编译：navic 每次都要编自己的 std；Go 用一个只装了 std 的私有缓存（日常情况），另给一行完全不带缓存的 Go
- 无改动重编译
- 改一个函数体后重编译
- 峰值内存（`/usr/bin/time -l` 的 maximum resident set size）

脚本不碰用户自己的 Go 缓存。

## 结果（Apple M 系列，macOS 15，Go 1.26）

第三轮（2026-11-13 深夜，M:N 运行时、并发 GC、编译器内部并行之后；8 核）：

| 行数 | 编译器 | 冷编译 | 无改动 | 改一个函数体 |
|---|---|---|---|---|
| 1 万 | navic | 0.95s / 377MB | 0.03s / 29MB | 0.96s / 380MB |
| 1 万 | go build（std 已缓存） | 0.37s / 135MB | 0.10s / 22MB | 0.36s / 137MB |
| 1 万 | go build（无缓存） | 2.23s / 297MB | | |
| 10 万 | navic | 8.62s / 2.45GB | 0.14s / 85MB | 8.71s / 2.43GB |
| 10 万 | go build（std 已缓存） | 2.73s / 895MB | 0.11s / 22MB | 2.64s / 902MB |
| 10 万 | go build（无缓存） | 2.57s / 910MB | | |

冷编译是 Go 的约 2.6 倍（1 万行）和 3.2 倍（10 万行）；比 Go 不带缓存（连 std 一起编）快。内存是 Go 的 2.7 倍（并发 GC 的周期里堆还在长）。

第二轮（2026-11-13 晚，加了 MIR 内联、常量原位读取、std 函数体延迟类型检查、可达性根收窄、固有 `to_string` 等之后；这次机器负载略高，Go 的数字也比第一轮慢一些）：

结论：

- 无改动重编译和 Go 持平（navic 的构建缓存）。
- 冷编译和改一个函数体后的重编译是 Go 的 3.5–6 倍（1 万行约 3.5–4.5 倍，10 万行约 6 倍）：navic 单线程，也没有函数粒度的增量缓存；Go 的编译器在包内并行：文件并发解析，函数的后端（SSA、寄存器分配、生成机器码）用 `-c=N` 个 worker 并发（只编一个包时 N 可到 GOMAXPROCS），类型检查是单线程的；改一个函数体也只重编那个包。
- 计划里 "M9 与 go build 持平" 的目标还没有达到。
